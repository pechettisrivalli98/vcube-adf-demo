-- 4. Data Engineering (Most Common Interview Use Case)
/*
Source Table: Sales_Staging
Target Table: Sales_Warehouse
You want to load only new records.

Why use LEFT JOIN?
Keeps all staging records.
Records already in the warehouse will match.
New records have NULL on the warehouse side and are inserted.

This is a common pattern for incremental loading in Azure Data Factory, Databricks, and SQL-based ETL processes.
-- without JOIN: Incremental load using watermark column/date column
	SELECT *
	FROM Orders
	WHERE LastModifiedDate >
	(
	SELECT MAX(LastModifiedDate)
	FROM DW_Orders
	);

Interview Answer:
"A LEFT JOIN is commonly used when we need all records from the primary table regardless of whether matching data exists in another table. In data engineering, a common use case is incremental loading, where we LEFT JOIN the staging table with the target table and select records where the target key is NULL. This helps identify new records that need to be loaded into the data warehouse."


SELECT s.*
FROM Sales_Staging s
LEFT JOIN Sales_Warehouse t
ON s.OrderID = t.OrderID
WHERE t.OrderID IS NULL;
*/

2. Data Engineering (Real-Time ETL): Suppose sales data arrives daily from two countries. Before loading into Azure Synapse, Snowflake, or Databricks Delta Lake, combine data from multiple countries into one unified dataset.

SELECT OrderID,
       CustomerID,
       Amount
FROM Sales_India

UNION

SELECT OrderID,
       CustomerID,
       Amount
FROM Sales_USA;


"In real-world Data Engineering projects, UNION is commonly used to combine data from multiple sources such as different branches, regions, or yearly tables into a single dataset. For example, if sales data is stored separately for India and the USA, we use UNION to create one consolidated report. UNION removes duplicate rows automatically, while UNION ALL retains duplicates and performs faster. In ETL pipelines, UNION ALL is generally preferred when source data is known to be unique or when duplicate records need to be preserved
*/

Data Engineer Interview Answer:
"A CROSS JOIN is used when we need every possible combination between two datasets. A common real-time use case is generating product variants, such as every combination of colors and sizes in an e-commerce application. In Data Engineering, CROSS JOIN is also used to generate test data, create store-date combinations for reporting, build employee-month records, or create all product-promotion combinations. Since it produces a Cartesian product, it should be used carefully on large datasets because the number of rows grows rapidly."
